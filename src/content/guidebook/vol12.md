## 序　本巻のねらいと読み方

本巻は、講義「企業経営とAI」第III部・第12回「新規事業創出」の詳しい解説書です。講義全体は「財務を中心に、AIで何が変わるか」を見る構成で、AI活用の3本柱（①業務効率化、②意思決定の高度化、③新規事業創出）のうち、本巻は③を扱います。

本巻を通じた問いは一つです。

> **作るのが安くなったら、何が難しくなるのか。**

生成AIのおかげで、試作品や説明用のWebページは、以前なら数か月かかったものが数日で作れるようになりました。ところが、「その商品を本当に買う人がいるか」「お金を払い続けてくれるか」を確かめる作業は、AIを使っても大きくは短くなりません。本巻は、このずれを出発点に、新規事業を**検証の速さ**と**採算の確かさ**の両面から考えます。

### 本巻で使う架空の会社

- **A社**：産業用部品をつくる中堅製造業（売上高約30億円、従業員約120人）。2026年度のROIC（投下資本利益率）は4.4%で、資本コスト6%を下回っています。本巻では、A社が自社の部品データを生かした新規事業「**部品の故障予兆サービス**」を検討する場面を追います。
- **B社**：地域の食品加工・卸（売上高約3.1億円、従業員約20人）。第4章の最後で、小さな会社の場合の考え方に使います。

> **【ポイント】** 本巻の数値・前提は、すべて学習用に作った架空のものです。実在の企業や市場のデータではありません。

### 学習目標

本巻を読み終えると、次の3つができるようになることを目指します。

1. 生成AIで「作る」コストが下がった一方、「検証する」コストは下がりにくい理由を、構築・計測・学習のループで説明できる。
2. CAC・LTV・粗利率などのユニットエコノミクスを計算し、新規事業の売上や利益、ROICへの影響につなげて説明できる。
3. 試作品（MVP）をAIで作り、その採算を疑って確かめる手順を、ワークシートに沿って実行できる。

## 第1章　なぜ今、新規事業か

> **【この章のポイント】**
>
> - 既存事業の利益率が下がると、ROICを資本コスト以上に戻すには「新しい稼ぎ方」が必要になります。
> - 生成AIで変わったのは、①作るコスト、②自社データの価値、③競争の速さ、の3つです。
> - 新規事業は最初に赤字が続く「Jカーブ」を描くため、財務の言葉で計画を語れることが欠かせません。

### 1.1　A社が直面している問題

A社は産業用部品をつくり、機械メーカーや工場に販売しています。売上高は2024年度の26億円から2026年度には30億円へ伸びました。しかし、原材料費の上昇を価格に十分転嫁できず、**粗利率は24%から21%へ下がっています**。その結果、2026年度のROICは4.4%で、資本コスト（投資家が期待する最低限の利回り）の6%を下回っています。

これは、「売上は増えているのに、使っているお金に見合う利益を出せていない」状態です。第4巻『財務ハブ：PL・BS・CFとROICツリー』で学んだROICツリーでいえば、利益率の枝が細くなっています。コスト削減（3本柱の①）や意思決定の改善（②）でも一定の改善はできますが、部品を売って終わりという今の稼ぎ方のままでは、価格競争から抜け出すのは簡単ではありません。

> **【例】** A社の営業部長は、大口顧客の工場長からこう言われました。「部品が壊れてから連絡をもらっても遅い。壊れる前に知らせてくれるなら、お金を払ってもいい」。A社の工場には、過去10年分の部品の検査データと故障・返品の記録があります。営業部長は、これを使えば「故障の予兆を知らせるサービス」ができるのではないかと考えました。

### 1.2　生成AIで何が変わったか

新規事業そのものは昔からある経営課題です。それでも「今」考える理由は、生成AIによって次の3つが変わったからです。

| 変わったこと | 以前 | 今 |
| --- | --- | --- |
| ① 作るコスト | 試作アプリは外注で数百万円・数か月 | AIに話しかけながら数日で試作（バイブコーディング） |
| ② 自社データの価値 | 社内に眠る記録で、使い道が少ない | AIで分析・予測に使え、商品の材料になる |
| ③ 競争の速さ | 同じ発想の競合が現れるまで時間がかかった | 誰でも同じAIで同じものを作れるため、すぐに似た商品が出る |

①はチャンス、③は脅威です。そして②は、③の脅威に対する一番の守りになります。**誰でも作れるものは差別化にならず、自社にしかないデータや現場の知識が差別化の源になる**からです。この考え方は第3章で詳しく扱います。

### 1.3　新規事業は財務のどこに効くか

新規事業がうまくいくと、売上の新しい柱ができ、利益率の高い収益が加わります。ROICツリーでいえば、分子のNOPAT（税引後営業利益）を増やす効果です。ただし、最初の数年は開発費や顧客獲得の費用が先に出ていき、利益はマイナスになります。累積の現金収支をグラフにすると、いったん下がってから上がる「J」の形になるため、これを**Jカーブ**と呼びます。

> **【経営者の視点】** 経営者が新規事業の提案を受けたときに知りたいのは、「アイデアが面白いか」よりも、①いつまでに、いくら赤字が出るか、②どの数字が見えたら続け、どの数字なら止めるか、の2点です。本巻の第4章と第8章は、この2つに答えるための章です。

> **【ポイント】** 新規事業は「夢を語る」ものではなく、「仮説を数字で確かめ、続けるか止めるかを決める」ものです。AIは確かめる回数を増やす道具として使います。

## 第2章　基礎：新規事業を語るための言葉

> **【この章のポイント】**
>
> - 「売り切り」と「継続課金（サブスクリプション）」では、お金の入り方が大きく違います。
> - 継続課金の採算は、粗利・CAC・LTV・解約率の4つでほぼ説明できます。
> - MVPは「小さな完成品」ではなく「仮説を確かめるための道具」です。

### 2.1　ビジネスモデル：売り切りと継続課金

**ビジネスモデル**とは、「誰に、何の価値を届け、どうやってお金をもらうか」の仕組みです。A社の今の事業は、部品を納めたときに代金をもらう**売り切り型**です。これに対して新しい故障予兆サービスは、毎月利用料をもらう<strong>継続課金型（サブスクリプション）</strong>です。

| 観点 | 売り切り型 | 継続課金型 |
| --- | --- | --- |
| 売上の入り方 | 販売したときにまとめて | 毎月少しずつ、続く限り |
| 大事な数字 | 販売数量・単価・粗利率 | 契約数・解約率・LTV |
| 最初の資金 | 製造のための在庫や設備 | 開発費と顧客獲得費が先に出る |
| うまくいくと | 売れた分だけ利益 | 顧客が積み上がり、収入が安定する |

### 2.2　粗利と粗利率

**粗利**は「売上 − 売上に比例してかかる費用（変動費）」、**粗利率**は「粗利 ÷ 売上」です。継続課金では、顧客を一人増やすごとにかかるクラウド利用料や通信費、サポートの手間が変動費になります。

> **【例】** A社の故障予兆サービスの前提（架空）：1顧客（1工場）あたり月額8万円。クラウド利用料・センサーの通信費・問い合わせ対応で月約2万円かかるとすると、月の粗利は6万円、粗利率は75%です。A社の部品事業の粗利率21%と比べると、かなり高いことがわかります。

### 2.3　CAC・解約率・LTV

| 用語 | 意味 | A社の前提（架空） |
| --- | --- | --- |
| **CAC**（顧客獲得コスト） | 新しい顧客1人を得るのにかかる費用。営業の人件費、展示会、導入支援など | 1顧客あたり60万円 |
| **解約率**（チャーンレート） | ある月に契約をやめる顧客の割合 | 月1.5% |
| **平均契約期間** | 「1 ÷ 月次解約率」でおおよそ計算できる | 約67か月（約5.6年） |
| **LTV**（顧客生涯価値） | 1人の顧客が契約期間全体でもたらす粗利。「月の粗利 ÷ 月次解約率」 | 6万円 ÷ 1.5% ＝ 400万円 |

この4つから、新規事業でよく使う指標が2つ作れます。

- **LTV/CAC**：「1人の顧客から得られる粗利」が「1人を獲得する費用」の何倍か。A社は400 ÷ 60 ＝ 約6.7倍です。一般に3倍以上が目安とされますが、業種や段階で変わります。
- **CAC回収期間**：獲得費用を月の粗利で取り戻すまでの月数。A社は60 ÷ 6 ＝ 10か月です。

> **【ポイント】** LTVは「売上」ではなく「粗利」で計算します。売上で計算すると、変動費の分だけ過大に見えてしまいます。また、解約率が少し動くだけでLTVは大きく変わります（第4章）。

### 2.4　MVPとバイブコーディング

**MVP**（Minimum Viable Product、実用最小限の製品）は、「顧客が本当に欲しがるか」を確かめるために作る、最小限の試作品です。説明ページだけ、画面の見本だけ、裏側は人が手作業で対応する、といった形もMVPになります。

**バイブコーディング**は、作りたいものを自然な言葉でAIに伝え、AIが書いたプログラムを動かしながら直していく作り方です。プログラミングの専門家でなくても、簡単な試作アプリや説明ページを数日で作れます。

> **【技術ノート】** バイブコーディングで作ったものは、「動く」ことと「安全に使える」ことが別です。顧客の本物のデータを入れる前に、認証やデータ保管の扱いを専門家に確認してもらう必要があります（第8章）。MVPは「検証用」と割り切り、本番用は作り直す前提で計画するのが安全です。

> **【要更新】** バイブコーディングの道具やできることは、数か月単位で変わります。授業の前に、使える道具と利用条件を確認してください。

## 第3章　考え方：作るのは安いが、検証は安くならない

> **【この章のポイント】**
>
> - 新規事業は「構築・計測・学習」のループを何周も回して仮説を確かめていく作業です。
> - 生成AIで「構築」は安くなりましたが、「計測」は顧客の時間と行動に依存するため、安くなりません。
> - 誰でも同じAIを使える時代には、アイデアは似通います。差は自社データと現場の知識から生まれます。

### 3.1　リーンスタートアップと「構築・計測・学習」

**リーンスタートアップ**は、エリック・リースが『リーン・スタートアップ』（2011年）で広めた考え方です。不確かな状況では、大きな計画を立てて一気に作るよりも、小さく作って顧客の反応を測り、そこから学んで方向を変える方が、結果として無駄が少ない、という考えです。

- **構築**：仮説を確かめるためのMVPを作る。
- **計測**：顧客に見せ、使ってもらい、反応を数字や言葉で集める。
- **学習**：結果を見て、続ける・変える（ピボット）・やめる、を決める。

### 3.2　生成AIで変わったところ、変わらないところ

![構築・計測・学習のループ · 3段階と戻り道](/images/guidebook/vol12-fig1.png)

*構築・計測・学習のループ · 3段階と戻り道*

図のように、AIで安く速くなったのは左の「構築」です。一方、真ん中の「計測」は顧客の時間をもらう必要があり、「学習」の判断は人が責任を持つため、この2つは大きくは短くなりません。その結果、ループ全体の速さを決めるのは「計測」になりました。

> **【例】** A社の推進担当は、故障予兆サービスの画面の試作品を、バイブコーディングで**3日**で作りました。ところが、それを持って大口顧客10社に話を聞きに行くと、訪問日程の調整だけで時間がかかり、全社の話を聞き終えるまで**2か月**かかりました。さらに、「毎月お金を払い続けてくれるか」（解約率）は、実際に半年〜1年使ってもらわないと分かりません。

検証が安くならない理由は、次の3つにまとめられます。

1. **顧客の時間は、AIで増やせない**：話を聞かせてくれる顧客の数と時間には限りがあります。
2. **「言うこと」と「すること」は違う**：「欲しい」と言った顧客が、実際にお金を払うとは限りません。本当に知りたいのは行動（申し込み、支払い、継続）です。
3. **時間が経たないと見えない数字がある**：解約率や利用の定着は、数か月単位でしか測れません。

> **【ポイント】** AIに「顧客役」をさせて意見を聞くことはできます。質問の練習や、見落としの洗い出しには役立ちます。しかし、AIの答えは本物の顧客の行動ではないため、「計測」の代わりにはなりません。

だからこそ、AI時代の新規事業では「何を作るか」よりも「**何を、どの順番で確かめるか**」を先に決めることが大切です。作るのが安いと、ついたくさん作ってしまい、確かめる作業が追いつかなくなります。

### 3.3　アイデアの同質化

生成AIに「製造業向けの新規事業アイデアを出して」と頼むと、とても速くたくさんの案が出てきます。しかし、同じような広い知識を学んだAIは、誰が聞いても似た案を出しやすくなります。AIを使ったアイデアは、一つひとつの質は上がっても、集団としては多様性が下がる傾向がある、という研究も報告されています（Doshi & Hauser, 2024, Science Advances）。

> **【要更新】** アイデアの同質化については研究が進んでいる段階です。授業で紹介する前に、引用する論文とその結論を確認してください。

同質化への対策は、AIに「自社にしかない材料」を渡すことです。A社の場合、10年分の検査データ、故障・返品の記録、営業が聞いてきた顧客の困りごとがそれに当たります。同じAIを使っても、渡す材料が違えば出てくる答えは違います。

### 3.4　AIファクトリー：使われるほど強くなる仕組み

イアンシティとラカーニは『AIファースト・カンパニー』（原題 *Competing in the Age of AI*、2020年）で、AIを中心にした企業の強さを「**AIファクトリー**」という言葉で説明しました。データを集め、予測し、その結果を実験で確かめ、またデータが増える、という歯車を会社の中に作る、という考え方です。その部品として、データの流れ道（パイプライン）、予測の仕組み（アルゴリズム）、実験の仕組み、それを支えるソフトウェア基盤が挙げられています。

> **【例】** A社の故障予兆サービスに当てはめると、契約する工場が増えるほど、部品の稼働データと故障の記録が集まり、予兆の当たり方が良くなります。当たり方が良くなると解約が減り、新しい顧客も得やすくなります。後から同じサービスを始めた競合は、このデータの蓄積をすぐには真似できません。

### 3.5　バーティカルAI：業界に特化して勝つ

**バーティカルAI**は、特定の業界や業務に絞って作られたAIのサービスです。汎用のAIは何にでも使える反面、各業界の細かい事情や専門用語、現場のデータまでは知りません。A社のように特定の分野で長く商売をしてきた会社にとっては、この「知らない部分」を埋めることが勝ち筋になります。

> **【経営者の視点】** 中堅企業が汎用AIそのもので大手と競争するのは現実的ではありません。しかし「自社の業界×自社のデータ×汎用AI」の組み合わせなら、大手が手を出しにくい小さな市場で一番になれる可能性があります。

### 3.6　Jカーブと「段階的に賭ける」考え方

新規事業は、最初にお金が出ていき、後から戻ってくるJカーブを描きます。そこで、一度に大きく投資するのではなく、確かめたいことを段階に分け、段階ごとに投資を決めます。

| 段階 | 確かめること | 主な物差し |
| --- | --- | --- |
| ① 課題の検証 | 顧客は本当に困っているか | 聞き取りで同じ困りごとを話す顧客の数 |
| ② 解決策の検証 | このサービスで解決できるか | 試作品の利用率、予兆の当たり方 |
| ③ 採算の検証 | お金を払い続けてくれるか | 有料契約数、解約率、CAC |
| ④ 拡大 | 同じやり方で顧客を増やせるか | LTV/CAC、累積キャッシュフロー |

AIで構築が安くなった分、①と②にかかるお金は小さくなりました。しかし③と④は、顧客の行動と時間が必要なことに変わりはありません。次の第4章では、③④で使う数字を詳しく見ていきます。

## 第4章　詳説：ユニットエコノミクスと財務への接続

> **【この章のポイント】**
>
> - 1顧客あたりの採算（ユニットエコノミクス）を、顧客数の増え方と固定費を加えて「5年の事業計画」に広げます。
> - 解約率・CAC・価格が少し変わるだけで、事業の価値（NPV）はプラスからマイナスに変わります。
> - 新規事業は最初のROICを下げますが、軽い資産で稼ぐ形なら、うまくいけばA社全体のROICを押し上げます。

### 4.1　出発点：1顧客あたりの採算

第2章で確認した数字をまとめます（すべて架空の前提、単位は万円）。

| 項目 | 計算 | 値 |
| --- | --- | --- |
| 月の粗利 | 月額8 − 変動費2 | 6（粗利率75%） |
| 平均契約期間 | 1 ÷ 解約率1.5% | 約67か月 |
| LTV | 6 ÷ 1.5% | 400 |
| LTV/CAC | 400 ÷ 60 | 約6.7倍 |
| CAC回収期間 | 60 ÷ 6 | 10か月 |

ここまでは「1人の顧客」の話です。しかし事業には、顧客が何人いてもかかる**固定費**（専任担当の人件費やシステムの維持費）と、最初に支払う**開発費**があります。ここから先は、それらを入れて事業全体で見ていきます。

### 4.2　事業計画に広げる

追加する前提は次のとおりです。

- 新規顧客：年30社（毎月2.5社）。獲得費用は30社 × 60 ＝ 年1,800
- 固定費：年1,200（専任担当の人件費とシステム基盤の維持費）
- 開発費：本番システム1,500を開始時に支払い、5年で償却（年300）。このほか、MVPの費用が50
- 税金と運転資本は、この節では入れません（税引前の計算）。

毎月「前月の顧客数 ×（1 − 解約率）＋ 新規顧客」で顧客数を計算し、年度ごとに集計すると次のようになります。

| 年度 | 年度末の顧客数 | 売上 | 粗利 | 獲得費用 | 固定費 | 償却費 | 営業利益 | キャッシュフロー |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1年目 | 27.6 | 1,477 | 1,108 | 1,800 | 1,200 | 300 | −2,192 | −1,892 |
| 2年目 | 50.7 | 3,886 | 2,915 | 1,800 | 1,200 | 300 | −385 | −85 |
| 3年目 | 69.9 | 5,896 | 4,422 | 1,800 | 1,200 | 300 | 1,122 | 1,422 |
| 4年目 | 86.0 | 7,572 | 5,679 | 1,800 | 1,200 | 300 | 2,379 | 2,679 |
| 5年目 | 99.4 | 8,970 | 6,727 | 1,800 | 1,200 | 300 | 3,427 | 3,727 |

営業利益は「粗利 − 獲得費用 − 固定費 − 償却費」、キャッシュフローは償却費を戻した「粗利 − 獲得費用 − 固定費」です。顧客を獲得する費用は先に出て、粗利はその後何年もかけて入ってくるため、最初の2年は赤字になります。

![本巻の試算モデル（架空の前提）· 開始時〜5年目の累積CF、税引前](/images/guidebook/vol12-fig2.png)

*本巻の試算モデル（架空の前提）· 開始時〜5年目の累積CF、税引前*

開始時の開発費とMVP費（計1,550）から累積の赤字はさらに深くなり、最も深いのは2年目です。この「谷」の深さが、会社がこの事業に用意しておくべき資金の量です。累積がプラスに戻るのは4年目、つまり**回収期間（ペイバック）は約3.8年**です。

この5年分のキャッシュフローを資本コスト6%で現在価値に戻して合計すると、**正味現在価値（NPV）は約2,690万円**です。

> **【ポイント】** このNPVは税引前で、6年目以降の稼ぎ（継続価値）も入れていない簡易版です。顧客数は5年目にまだ約100社で、このままなら約167社（年30社 ÷ 年間解約率）まで増え続けます。税金や継続価値を含めた正式なNPVの計算は、第7巻『AI投資の評価：ROI・TCO・NPV』で扱います。

### 4.3　感度分析：どの数字が崩れると危ないか

事業計画は前提の積み重ねです。そこで、前提を1つずつ変えて結果がどう動くかを見ます。これを**感度分析**といいます。

| ケース | LTV | LTV/CAC | CAC回収期間 | 5年NPV（税引前） |
| --- | --- | --- | --- | --- |
| 基本ケース | 400 | 約6.7倍 | 10か月 | ＋2,690 |
| 解約率が月3%に悪化 | 200 | 約3.3倍 | 10か月 | −806 |
| CACが120に倍増 | 400 | 約3.3倍 | 20か月 | −4,893 |
| 月額を6に値下げ | 約267 | 約4.4倍 | 15か月 | −2,936 |

この表から、大事なことが2つ読み取れます。

1. **LTV/CACが3倍を超えていても、事業全体では赤字になり得る**。LTV/CACは1顧客の採算であり、固定費や開発費は入っていないからです。これが演習②「採算を疑う」の中心になる考え方です。
2. **価格・解約率・CACは、どれも少しの変化で結論を反転させる**。試算すると、NPVがゼロになるのは、解約率なら約月2.6%、CACなら約81、月額なら約7、新規顧客数なら年約21社のときです。基本ケースとの差は意外に小さいことに注意してください。

### 4.4　A社の財務への接続：売上・利益・ROIC

基本ケースが実現した場合、A社全体の数字にどう効くかを見ます（A社の2026年度の数字を動かさず、新規事業の分だけを足した試算です）。

- **売上**：5年目の売上約0.9億円は、A社の売上30億円の約3%です。売上としては小さな柱です。
- **営業利益**：5年目の営業利益約3,400万円は、A社の営業利益1.10億円の約31%に当たります。売上は3%でも、利益への効きは大きいのです。粗利率が75%と高いためです。
- **ROIC**：A社のROICは「税引後営業利益（NOPAT）÷ 投下資本」で2026年度は0.77億円 ÷ 17.52億円 ＝ 4.4%です。新規事業を加えると、次のように動きます。

| 時点 | A社全体のROIC | 理由 |
| --- | --- | --- |
| 現在（新規事業なし） | 4.4% | ― |
| 1年目 | 約3.5% | 赤字（税引後で約−1,530万円）でNOPATが減る |
| 3年目 | 約4.8% | 黒字に転じ、NOPATが増え始める |
| 5年目 | 約5.7% | NOPATが約0.24億円増える一方、投下資本の増加は約0.07億円にとどまる |

分子（NOPAT）は大きく増え、分母（投下資本）はほとんど増えません。工場や在庫を必要としない**資産の軽い稼ぎ方**だからです。ただし、5年目でも資本コスト6%には届きません。新規事業だけでROICを立て直すのではなく、既存事業の効率化（3本柱の①）や価格・在庫の判断の改善（②）と組み合わせて考える必要があります。

> **【経営者の視点】** 新規事業は「最初の数年、会社のROICを下げる」ことを前提に承認するものです。取締役会では、「いつ、どこまで下がり、いつ戻るか」を先に示しておくと、途中で数字が悪く見えても、計画どおりかどうかを冷静に議論できます。

### 4.5　撤退の条件を数字で決めておく

感度分析で分かった「NPVがゼロになる線」は、そのまま撤退や見直しの物差しになります。A社では、事業を始める前に次のように決めておくことにしました（架空）。

| 物差し | 見直しの線 | 撤退を検討する線 |
| --- | --- | --- |
| 月次解約率（有料化後6か月の平均） | 2.0%超 | 2.5%超 |
| CAC | 70超 | 80超 |
| 新規顧客数（年間） | 25社未満 | 20社未満 |
| 累積キャッシュフロー | 計画より500悪化 | 計画より1,000悪化 |

撤退の条件を先に決めるのは、始めた事業への愛着や「ここまでお金をかけたのだから」という気持ち（サンクコストへのこだわり）で判断が曇るのを防ぐためです。運用の仕組みは第8章で扱います。

### 4.6　よくある質問

**Q1. CACには何を入れればよいですか。** A. 新しい顧客を得るために使った費用をすべて入れます。広告費だけでなく、営業担当の人件費のうち新規開拓に使った分、無料の導入支援や試用期間の費用も含めます。小さく見積もると、LTV/CACが良く見えすぎます。

**Q2. 解約率は事業を始める前に分かりません。どうすればよいですか。** A. 最初は似たサービスの公開情報や、既存顧客の取引の続き方を参考に仮置きし、感度分析で幅を持たせます。そのうえで、有料の試験導入を早めに始め、実際の数字に置き換えていきます。

**Q3. AIで工場のデータを分析するなら、変動費はもっと大きくなりませんか。** A. なり得ます。AIの利用料は使う量に応じて増えることが多く、一般的なソフトウェア事業より粗利率が低くなりやすいと言われます。粗利率の前提は、MVPの段階で実際の利用料を測って確かめるべき項目の一つです。

### 4.7　小さな会社の場合：B社の考え方

B社（地域の食品加工・卸、従業員約20人）は、売上の半分以上を大手スーパー1社に頼っています。そこで、地域の飲食店向けに「仕込み済み食材の定期便と、AIによる発注量の提案」を検討しています（架空）。

| 項目 | B社の前提（架空、単位：万円） |
| --- | --- |
| 月額（サービス料） | 3、変動費1.2 → 月の粗利1.8 |
| CAC | 15（営業の訪問と試食） |
| 解約率 | 月3% → LTVは1.8 ÷ 3% ＝ 60 |
| LTV/CAC・CAC回収期間 | 4.0倍・約8か月 |
| 固定費 | 兼務担当1人分で年300（月約25） |

小さな会社でいちばん大事なのは、「固定費を賄うには何店必要か」です。月約25 ÷ 1.8 ＝ **約14店**です。B社は、まず14店に届く見込みがあるかを、既存の取引先への聞き取りで確かめます。MVPは、注文フォームと発注量の提案を表計算で返すだけの簡単なもので十分です。大きな開発費をかけない分、Jカーブの谷も浅くすみます。

> **【ポイント】** B社にとって、この事業の価値は利益だけではありません。大手1社への依存を下げ、売上と入金のリスクを分散する効果もあります。こうした効果も、判断の材料として言葉にしておきましょう。

## 第5章　AI活用の型

> **【この章のポイント】**
>
> - AIは「構築・計測・学習」のどの段階でも役立ちますが、役割は段階ごとに違います。
> - AIを使った新規事業には、①自社データのサービス化、②バーティカルAI、③社内ノウハウの外販、の3つの型があります。
> - 仕組みを全部自分で作る必要はありません。「作る・買う・組む」を分けて考えます。

### 5.1　ループの段階ごとのAIの役割

| 段階 | AIに任せられること | 人が握ること |
| --- | --- | --- |
| 課題を探す | 業界の公開情報の整理、問い合わせや返品記録の要約・分類 | 誰に話を聞くか決め、実際に会う |
| 構築 | 画面の試作、説明ページ、料金表の案、提案書の下書き | 確かめたい仮説を一つに絞る |
| 計測 | 聞き取りの質問案、記録の文字起こしと分類、利用ログの集計 | 顧客の本音と行動を引き出す |
| 学習 | 結果の整理、反対意見の洗い出し、採算の再計算 | 続ける・変える・やめるの判断と責任 |

> **【例】** A社の推進担当は、過去3年分の問い合わせ記録をAIに要約させ、「突然の故障でラインが止まった」という相談がどの業種に多いかを分類しました。その結果をもとに、聞き取り先の10社を選びました。話を聞く先を選ぶ作業はAIで短くなりましたが、訪問して話を聞く作業そのものは短くなりませんでした。

### 5.2　AIを使った新規事業の3つの型

| 型 | 中身 | 強み | 注意点 |
| --- | --- | --- | --- |
| ① 自社データのサービス化 | 本業でたまったデータをAIで分析し、予測や助言として売る（A社の故障予兆） | 競合が真似しにくい | 顧客のデータを使うなら契約と同意が必要 |
| ② バーティカルAI | 特定の業界の業務に絞ったAIサービス（例：部品の図面から見積もりを作る） | 業界の言葉と慣習を知っている | 市場が小さい。汎用AIの進歩で差が縮むことがある |
| ③ 社内ノウハウの外販 | 自社の効率化のために作ったAIの仕組みを、同業や取引先に提供する | 自社で効果を確かめ済み | 他社向けのサポート体制が別に必要 |

3つの型に共通するのは、**自社にしかないもの（データ・業界知識・実績）を出発点にしている**ことです。第3章の「アイデアの同質化」への答えが、そのまま事業の型になっています。

> **【経営者の視点】** 3本柱の①（業務効率化）で社内に作った仕組みが、③の種になることがあります。社内のAI活用を「コスト削減で終わり」にせず、「他社も困っていないか」を問い直すと、新規事業の入口が見つかります。

### 5.3　作る・買う・組む

新規事業のAIの仕組みを、すべて自社で開発する必要はありません。MIT NANDAの報告書は、企業の生成AIの取り組みでは、外部の仕組みを買う、または他社と組む方が、内製より成功しやすい傾向を指摘しています。

> **【要更新】** MIT NANDAの報告書（『The GenAI Divide』、2025年7月）は速報版で査読を経ておらず、調査方法にも批判があります。授業では「傾向を示す一つの調査」として紹介し、最新の版とその後の議論を確認してください。

A社の故障予兆サービスに当てはめると、次のように分けられます。

- **作る**：部品ごとの故障の見分け方（どの数値がどう変わると危ないか）。ここがA社の差別化の核です。
- **買う**：データを集めて保管するクラウド、文章で報告を作る生成AI、請求や契約管理の仕組み。
- **組む**：センサーの取り付けは設備工事会社と、大口顧客への販売は既存の営業経路と。

> **【技術ノート】** 「買う」部分の利用料は、使う量に応じて増える変動費になることが多く、粗利率を直接左右します。一方、「作る」部分の開発費は、一定の要件を満たせばソフトウェアとして資産に計上し、何年かに分けて償却します（第4章の開発費1,500を5年で償却したのはこの扱いです）。どちらになるかで、損益計算書と貸借対照表の見え方が変わります。

## 第6章　実務の手順：仮説からMVP、計測、判断まで

> **【この章のポイント】**
>
> - 手順は「仮説を書く → 確かめる順番を決める → MVPを作る → 計測する → 採算を計算し直す → 判断する」の6段階です。
> - AIへの指示（プロンプト）には、確かめたい仮説と範囲を書きます。
> - AIの答えは、「確認のポイント」に沿って必ず人が確かめます。

### ステップ1　仮説を書く

新規事業のアイデアを、次の4つの仮説に分けて書きます。どれか一つでも外れれば、事業は成り立ちません。

| 仮説 | A社の例 |
| --- | --- |
| 顧客：誰が困っているか | 部品の故障でラインが止まると損失が大きい工場 |
| 課題：何に困っているか | 故障が突然起き、交換部品もすぐに届かない |
| 解決策：何で解決するか | 部品のデータから故障の予兆を知らせ、交換を予定に組み込める |
| 支払い：いくら払うか | 1工場あたり月額8万円なら払う |

### ステップ2　確かめる順番と物差しを決める

一番外れそうで、外れたときの影響が大きい仮説から確かめます。そのうえで、「何が起きたら仮説が正しいとみなすか」を、**計測する前に**数字で決めます。後から決めると、都合のよい解釈に流れやすいからです。

> **【例】** A社は「支払い」の仮説が最も危ういと考えました。物差しは「聞き取りした10社のうち3社以上が、有料の試験導入（月額4万円、3か月）に申し込む」としました。「良いですね」という言葉ではなく、申し込みという行動を数えるのがポイントです。

### ステップ3　MVPをバイブコーディングで作る

MVPは、ステップ2で決めた仮説を確かめるのに必要な分だけ作ります。A社の場合、本物の予測機能は不要で、「予兆が出たらどう見えるか」を示す画面と、料金を示す説明ページがあれば十分です。

```
【プロンプト例】
あなたはWeb画面の試作を手伝う開発者です。
工場の保全担当者向けに、部品の故障予兆を知らせるサービスの「画面の試作」を、HTML 1ファイルで作ってください。
目的：顧客に見せて「この画面に月額8万円を払うか」を聞くため。実際の予測は不要で、数値はすべて仮のものでよい。
画面：①部品ごとの状態一覧（正常／注意／要交換）、②「要交換」を押すと交換の推奨時期と理由が出る、③料金と申し込みボタン。
制約：個人情報や顧客名は入れない。外部へのデータ送信はしない。画面に「試作品」と表示する。
```

**回答の確認ポイント**

- 仮説を確かめるのに必要な画面だけになっているか（作り込みすぎていないか）。
- 「試作品」であることが顧客に分かるか。本物の予測であるかのように見せていないか。
- 外部への通信や、入力された情報の保存が勝手に入っていないか。

### ステップ4　計測する

聞き取りでは、未来のこと（「使いますか」）より、過去の事実（「最後に突然の故障があったのはいつで、いくら損しましたか」）を聞きます。過去の事実は、相手への気遣いで歪みにくいからです。

```
【プロンプト例】
工場の保全担当者に30分の聞き取りをします。確かめたい仮説は「部品の突然の故障で大きな損失が出ており、予兆を知るために月額を払う」です。
過去の事実を聞く質問を8つ作ってください。「使いたいですか」のような未来の意向を聞く質問と、答えを誘導する質問は避けてください。各質問に、何を確かめるための質問かを添えてください。
```

**回答の確認ポイント**

- 誘導的な質問（「お困りですよね」）が混ざっていないか。
- 損失の金額や頻度など、採算の計算に使える数字を聞ける質問があるか。
- 聞き取り記録をAIに要約させる場合は、相手の了解を得、社名や個人名を伏せてから渡す。

### ステップ5　採算を計算し直す

計測で分かった数字（申し込み率、支払ってもよい金額、導入にかかった手間）で、第4章の前提を置き換えます。AIに表計算の式を作らせると便利ですが、計算結果は必ず検算します。

**回答の確認ポイント**

- LTVを売上ではなく粗利で計算しているか。
- 固定費・開発費を入れた事業全体の数字（累積キャッシュフロー、NPV）まで出しているか。
- 1年目の売上を「年末の顧客数 × 12か月」で計算するような、過大な計算になっていないか。

### ステップ6　判断する

結果をもとに、「続ける」「変える（顧客、価格、解決策のどれかを変える）」「やめる」のどれかを決め、理由と一緒に記録します。AIに「この結果を見て、続けるべきでない理由を挙げて」と反対意見を出させると、推進担当の思い込みに気づきやすくなります。ただし、判断するのは人です。

> **【ポイント】** AIで構築が安くなった分、「変える」のコストも下がりました。画面や説明ページを作り直して、別の顧客や別の価格でもう一周回すことが簡単になっています。

## 第7章　ケース

> **【この章のポイント】**
>
> - A社の架空ケースで、試験導入の結果を採算に戻して「変える」を決める流れを追います。
> - 「生成AIの取り組みの95%は成果が出ていない」という調査を、新規事業のJカーブの視点から読み直します。

### 7.1　A社ケース：試験導入から分かったこと（架空）

**経緯**：A社は、バイブコーディングで3日で作った画面の試作品を持って、10社に2か月かけて話を聞きました。そのうち4社が有料の試験導入（月額4万円、3か月）に申し込み、事前に決めた物差し（3社以上）を超えました。

**試験導入の3か月で分かったこと**

- 予兆の当たり方は、部品の種類によって大きく違った。よく当たるのは、A社に故障の記録が多く残っている2種類だけだった。
- 4社のうち1社は「警告が多すぎて現場が見なくなった」として、継続しなかった。
- 顧客の工場でセンサーを取り付ける工事が必要で、導入の手間が想定より大きかった。このままだとCACは60ではなく75程度になりそうだ。

**採算への戻し方**：CACを75に置き換えて第4章の試算をやり直すと、LTV/CACは約5.3倍、CAC回収期間は12.5か月、5年NPVは約＋790となり、まだプラスです。ただし「見直しの線」（CAC 70超）は超えています。また、警告の多さで解約が起きると、解約率の前提も崩れます。

**A社の判断**：「変える」。対象をよく当たる2種類の部品に絞り、警告の出し方を「要交換」に限定しました。センサーの取り付けは設備工事会社と組んで手間を減らし、CACを60に戻すことを次の周の目標にしました。

> **【経営者の視点】** このケースで大事なのは、試験導入の「感想」ではなく「採算の前提のどれが動いたか」で議論していることです。現場の声をCACや解約率に置き換えると、経営会議でも共通の言葉で話せます。

### 7.2　論争：「95%は成果が出ていない」をどう読むか

MIT NANDAの報告書『The GenAI Divide』（2025年7月）は、組織の95%が生成AIの試験的な取り組みから、損益に表れる成果を得ていないと報告しました。この数字は広く報道されましたが、速報版で査読がなく、測定期間（6か月）や調査対象の選び方に批判があります。

新規事業の視点からは、特に「6か月」という期間が問題になります。第4章のA社の試算では、営業利益が黒字になるのは3年目、累積がプラスになるのは4年目でした。この事業を始めて半年の時点で損益を測れば、「成果が出ていない」側に数えられます。

だからといって「95%は誤りだ」と結論するのも早計です。大事なのは次の2点です。

1. **どの段階を、どの物差しで測っているか**を確かめる。新規事業の初期は、損益ではなく、申し込み数・解約率・CACで測るべき段階です。
2. **いつ、どの数字になっていなければ失敗とみなすか**を先に決めておく。これがないと、「まだJカーブの途中だから」という言い訳がいつまでも使えてしまいます。

> **【ポイント】** Jカーブは、早すぎる評価で良い事業を潰す危険と、「まだ途中」を理由に悪い事業を続ける危険の、両方を生みます。段階ごとの物差しと撤退の条件は、その両方への備えです。

### 7.3　考えてみよう：アイデアの同質化とA社の競争力

A社の競合も、同じ生成AIを使って「部品の故障予兆サービス」を思いつくかもしれません。そのとき、A社が勝てる理由は何でしょうか。第3章のAIファクトリーの考え方を使うと、「先に始めてデータを蓄えた側が有利になる」と説明できます。一方で、競合がより多くの顧客を持っていれば、後から追い抜かれるかもしれません。この問いは、第11章の討議課題で扱います。

## 第8章　ガバナンス：撤退・データ・権利・安全

> **【この章のポイント】**
>
> - 撤退の条件は、決めるだけでなく、「誰が、いつ、何を見て判断するか」まで決めて初めて効きます。
> - AIを使ったサービスを売ると、会社はAIを「使う側」から「提供する側」になります。責任の範囲が広がります。
> - バイブコーディングで作ったMVPは、「検証用」と「本番用」を分けて管理します。

### 8.1　撤退の条件を運用する仕組み

第4章で決めた撤退の条件を、次のような仕組みで運用します。

- **段階ごとの予算**：第3章の4つの段階（課題・解決策・採算・拡大）ごとに予算を分け、次の段階に進むときに改めて承認します。
- **定期の判断会議**：四半期ごとに、物差しの実績と「続ける・変える・やめる」の判断を記録します。
- **判断する人を分ける**：推進担当は事業に思い入れがあり、「やめる」を言い出しにくい立場です。判断は、経営陣と財務担当を含む会議体で行います。
- **やめたことを評価する**：条件どおりにやめた判断は「失敗」ではなく「検証の成果」として扱います。そうしないと、次に手を挙げる人がいなくなります。

### 8.2　顧客のデータと同意

故障予兆サービスは、顧客の工場の稼働データを使います。このデータは顧客にとって大切な情報です。契約で次の点を決めておく必要があります。

- データを何に使うか（その顧客への予兆だけか、他の顧客向けの予測の精度向上にも使うか）。
- 他の顧客に役立てる場合、どのように加工して、顧客が特定されないようにするか。
- 契約をやめたとき、データをどう扱うか。

> **【ポイント】** 第3章のAIファクトリーは、「顧客が増えるほどデータが増えて強くなる」仕組みでした。しかし、そのデータを使う同意を得ていなければ、歯車は回りません。同意の取り方は、競争力そのものに関わる経営の課題です。

### 8.3　AIで作ったコードや文章の権利

バイブコーディングで作ったプログラムや、AIが書いた説明ページの文章について、次の点を確かめます。

- **利用規約**：使ったAIの道具の利用規約で、生成物を商用に使えるか。
- **著作権**：AIが生成したものに著作権が認められるかは、人がどれだけ創作的に関わったかによります。自社の権利として守りたい部分（第5章の「作る」部分）は、設計の記録を残しておきます。
- **他人の権利の混入**：生成されたコードに、利用条件のある公開ソフトウェアや他社の文章が混ざっていないか。

> **【要更新】** AIと著作権の関係は、国内外で議論と制度の整備が続いています。授業の前に、文化庁の考え方の整理や関連する判例の最新状況を確認してください。具体的な判断は、弁護士などの専門家に相談してください。

### 8.4　バイブコーディングで作ったMVPの安全

| 確認すること | なぜ必要か |
| --- | --- |
| 本物の顧客データを入れない（仮のデータで見せる） | 検証用の仕組みは、守りが十分でないことが多い |
| パスワードや外部サービスの鍵をプログラムに直接書かない | 公開したときに第三者に見られる |
| ログインなどの認証を、自作せず実績のある仕組みで行う | 自作の認証は穴が生じやすい |
| 本番に使う前に、専門家がコードを確認する | AIのコードは「動く」が「安全」とは限らない |
| 「試作品」と明記し、使う期間を決める | 検証用がそのまま本番になるのを防ぐ |

### 8.5　「AIを提供する側」になるということ

AI事業者ガイドラインは、AIに関わる事業者を「開発者」「提供者」「利用者」に分けて、それぞれの留意点を示しています。社内でAIを使うだけならA社は「利用者」ですが、故障予兆サービスを顧客に売れば「提供者」の立場にもなります。予兆が外れたときの説明や、顧客への情報提供の責任が新たに生まれます。

> **【経営者の視点】** 「予兆が外れて故障したら誰が責任を持つか」は、契約書に書かなければならない問題です。予兆は「保証」ではなく「判断の材料」であること、交換を決めるのは顧客であることを、契約と画面の両方で伝えます。

> **【要更新】** AI事業者ガイドラインは改訂が重ねられています（本巻執筆時点は第1.2版）。また、人工知能基本計画は、業界に特化したAIを日本の勝ち筋の一つとしています。どちらも授業の前に最新版を確認してください。

**やり方**

2. 下の表の各項目を自分で計算し直し、AIの答えと比べます。
3. 前提を1つずつ変え、「結論がひっくり返る線」を探します（第4章の感度分析）。

**記入欄と記入例（A社、単位：万円）**

| 項目 | 自分の計算 | AIの答え | 一致？違いの理由 |
| --- | --- | --- | --- |

> **【ポイント】** 記入例の×は、どれも事業を「良く見せる」方向の誤りです。AIの計算はもっともらしく見えるので、特に「何が入っていないか」を疑ってください。

## 第11章　確認テストと討議課題

### 11.1　確認テスト（9問）

1. 構築・計測・学習のループのうち、生成AIで最も安く・速くなった段階はどれですか。
2. AI時代にループ全体の速さを決める「新しいボトルネック」はどの段階ですか。理由を1つ挙げてください。
3. 月額10万円、変動費月額4万円、月次解約率2%のサービスのLTVはいくらですか。
4. 問3のサービスのCACが100万円のとき、LTV/CACとCAC回収期間を求めてください。
5. 「LTV/CACが3倍を超えていれば、事業全体のNPVは必ずプラスになる」。正しいですか。理由も答えてください。
6. A社の試算で、新規事業の1年目にA社全体のROICが4.4%から約3.5%に下がるのはなぜですか。
7. 新規事業が「資産の軽い稼ぎ方」であることが、ROICにとって有利なのはなぜですか。
8. イアンシティとラカーニの「AIファクトリー」とは、どのような仕組みですか。一文で説明してください。
9. バイブコーディングで作ったMVPに、本物の顧客データを入れる前に必要なことを2つ挙げてください。

### 11.2　解答と解説

1. **構築**。試作品や説明ページを、バイブコーディングで数日で作れるようになりました（3.2）。
2. **計測**。顧客の時間はAIで増やせない、「言うこと」と「すること」は違う、解約率など時間が経たないと見えない数字がある、のいずれか（3.2）。
3. **300万円**。月の粗利は10 − 4 ＝ 6万円、LTVは6 ÷ 2% ＝ 300万円です。売上10で計算して500万円とするのは誤りです（2.3）。
4. **LTV/CACは3.0倍、CAC回収期間は約17か月**（100 ÷ 6 ＝ 約16.7）。
5. **正しくありません**。LTV/CACは1顧客の採算で、固定費や開発費を含みません。A社でも、解約率3%のケースはLTV/CACが約3.3倍でもNPVは約−806万円でした（4.3）。
6. 開発費や顧客獲得費用が先に出て新規事業が赤字になり、**分子のNOPATが減る**からです。Jカーブの谷の部分に当たります（4.4）。
7. 工場や在庫を必要としないため、**分母の投下資本がほとんど増えず、利益の増加がそのままROICを押し上げる**からです。A社の5年目では、NOPATが約0.24億円増える一方、投下資本の増加は約0.07億円でした（4.4）。
8. 例：「データを集めて予測し、その結果を実験で確かめ、得られたデータでまた予測を良くする歯車を、会社の中心に置く仕組み」（3.4）。
9. 例：①専門家によるコードの確認、②実績のある仕組みでの認証、③パスワードや鍵をコードに書かないこと、④顧客との契約でデータの使い道と同意を決めること、などから2つ（8.2、8.4）。

### 11.3　討議課題（3問）

1. **同質化と競争力**：競合が同じ生成AIを使って、A社とほぼ同じ故障予兆サービスを始めたとします。A社が勝ち続けるための条件は何でしょうか。AIファクトリー、データの同意、顧客数の観点から議論してください。
2. **続けるか、変えるか、やめるか**：有料化から6か月の平均解約率が月2.3%でした。「見直しの線」（2.0%）は超え、「撤退を検討する線」（2.5%）は超えていません。あなたが経営会議の一員なら、何を追加で確かめ、どう判断しますか。
3. **自社に当てはめる**：第5章の3つの型（自社データのサービス化、バーティカルAI、社内ノウハウの外販）のうち、あなたの会社（または想定する会社）で最も現実的なのはどれですか。「自社にしかないもの」と「資金の谷の深さ」の2つの言葉を使って説明してください。

### A. 用語集（括弧内は初出の節）

| 用語 | 意味 |
| --- | --- |
| ROIC（投下資本利益率）（1.1） | 税引後営業利益 ÷ 事業に使っている資本。使っているお金に対してどれだけ稼いだか |
| 資本コスト（1.1） | 投資家や貸し手が期待する最低限の利回り。A社は6% |
| 粗利・粗利率（1.1、2.2） | 売上 − 変動費。粗利率は粗利 ÷ 売上 |
| Jカーブ（1.3） | 最初に赤字や支出が先行し、後から回復する形の曲線 |
| NOPAT（税引後営業利益）（1.3） | 営業利益 ×（1 − 税率）。ROICの分子 |
| ビジネスモデル（2.1） | 誰に、何の価値を届け、どうやってお金をもらうかの仕組み |
| 売り切り型・継続課金型（2.1） | 販売時に代金をもらう型と、毎月利用料をもらう型（サブスクリプション） |
| 変動費（2.2） | 売上や顧客数に比例して増える費用 |
| CAC（顧客獲得コスト）（2.3） | 新しい顧客1人を得るのにかかる費用 |
| 解約率（チャーンレート）（2.3） | ある期間に契約をやめる顧客の割合 |
| LTV（顧客生涯価値）（2.3） | 1人の顧客が契約期間全体でもたらす粗利。月の粗利 ÷ 月次解約率 |
| LTV/CAC・CAC回収期間（2.3） | 1顧客の採算の指標。獲得費用の何倍稼ぐか、何か月で取り戻すか |
| MVP（実用最小限の製品）（2.4） | 仮説を確かめるための最小限の試作品 |
| バイブコーディング（2.4） | 自然な言葉でAIに指示し、AIが書いたプログラムを動かしながら直す作り方 |
| リーンスタートアップ（3.1） | 小さく作って測り、学んで方向を変えることを繰り返す新規事業の進め方 |
| 構築・計測・学習（3.1） | リーンスタートアップの基本ループ |
| ピボット（3.1） | 検証の結果を受けて、顧客・価格・解決策などの方向を変えること |
| アイデアの同質化（3.3） | 同じAIを使うことで、多くの人のアイデアが似通ってくる現象 |
| AIファクトリー（3.4） | データ・予測・実験の歯車を中心に置く企業の仕組み（Iansiti & Lakhani） |
| バーティカルAI（3.5） | 特定の業界や業務に絞って作られたAIサービス |
| 固定費（4.1） | 顧客数に関係なくかかる費用 |
| 回収期間（ペイバック）（4.2） | 累積キャッシュフローがプラスに戻るまでの期間 |
| NPV（正味現在価値）（4.2） | 将来のキャッシュフローを資本コストで現在の価値に戻して合計したもの |
| 継続価値（4.2） | 計画期間より後の稼ぎの価値 |
| 感度分析（4.3） | 前提を1つずつ変えて、結果がどう動くかを見る分析 |
| サンクコスト（4.5） | すでに使って取り戻せない費用。将来の判断には入れないのが原則 |
| 作る・買う・組む（5.3） | 仕組みを自社開発するか、外部から購入するか、他社と提携するかの選択 |
| AI提供者（8.5） | AIを組み込んだサービスを他者に提供する事業者（AI事業者ガイドラインの区分） |

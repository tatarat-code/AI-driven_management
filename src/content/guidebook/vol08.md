本書は、生成AIを使って会社の戦略を考え、中期計画を立てるための手引きである。講義「企業経営とAI」第8回に対応するが、単独でも読めるように書いた。試作版 v0.2（准初級向け）。

## 序 本書の使い方

### この巻で身につくこと

本書を読み終えると、次の4つができるようになる。

1. 戦略立案の仕事のうち、生成AIが得意な部分と苦手な部分を見分けられる（ジャグド・フロンティア）。
2. 人とAIの役割分担を、仕事の性質に合わせて「ケンタウロス型」と「サイボーグ型」から選べる。
3. 生成AIを使って3つのシナリオを作り、それぞれの財務への影響（ROIC）を計算して中期計画にまとめられる。
4. AIを「反対意見を言う役（レッドチーム）」として使い、自分たちの計画の弱点を見つけられる。

なかでも1の「ジャグド・フロンティア」は、本講義全体で何度も使う大切な考え方である。本書では第4章を丸ごと使って説明する。

### 対象読者

- 中期経営計画や事業計画を作る立場にある経営者・経営企画の担当者
- 生成AIで資料づくりはしているが、「戦略を考える」ことにどこまで使ってよいか迷っている社会人
- 技術には詳しいが、経営戦略の考え方に慣れていない理系の大学院生・技術者
- 講義「企業経営とAI」の受講者（第8回の予習・復習）

経営戦略の予備知識は求めない。SWOT分析やシナリオプランニングといった道具は、第2章で一から説明する。ROIC（投下資本利益率）は第4巻で詳しく扱うが、本書でも必要な範囲で説明する。

### 本書で使う架空の会社「A社」

本書の例には、講義全体で使う架空の会社「A社」が登場する。A社は、部品を仕入れて加工し、企業に販売するB2Bの製造・商社で、売上は約30億円、従業員は120名である。

A社は売上を伸ばしてきたが、値引きで受注を取りに行った結果、粗利率（売上に対する商品そのもののもうけの割合）が24.0%から21.0%に下がった。売掛金や在庫も膨らみ、ROICは8.4%から4.4%に落ちている（詳しくは第4巻）。社長は来年度からの3か年の中期経営計画を作ることにし、経営企画の担当者に「今年は生成AIも使って、しっかりした計画を作ってほしい」と頼んだ。本書では、この中期計画づくりを例に、戦略立案とAIの付き合い方を学んでいく。

## 1 なぜ戦略立案にAIなのか

**【この章のポイント】** 生成AIは、戦略立案の仕事を大きく速くし、質を上げることがある。その一方で、仕事の種類によっては、AIを使った方がかえって間違いが増える。この「効くところと効かないところが入り組んでいる」ことを知るのが、本書の出発点である。

### 1.1 戦略立案の仕事の大半は「調べること」だった（基礎）

中期経営計画や新しい事業の計画を作るとき、担当者の時間の多くは「調べること」と「まとめること」に使われてきた。

- 業界の動向、競合の決算、取引先の動き、法律や補助金の変化を調べる。
- 社内の売上や利益のデータを集め、部門ごとに整理する。
- それらをもとに、経営会議の資料を作る。

この作業に時間がかかるので、計画はどうしても「一つの未来」を前提にしたものになりやすい。「もし景気が悪くなったら」「もし競合が値下げしたら」という別の未来をいくつも考える余裕がないのである。

生成AIは、この「調べる」「まとめる」「下書きする」を大幅に速くする。その分の時間を、「複数の未来を比べる」「計画の弱点を探す」といった、本来の戦略を考える仕事に回せるようになる。

### 1.2 AIで「速く、うまく」なった実験（基礎）

AIが知的な仕事をどれだけ変えるかを確かめた、有名な実験がある。ボストンコンサルティンググループ（BCG）とハーバード大学などの研究者が、2023年に同社のコンサルタント758人を対象に行ったものである。参加者は、新しい飲料の企画を考える、市場を分析する、といった仕事を、AIを使うグループと使わないグループに分かれて行った。

AIが得意な種類の仕事では、AIを使ったグループの成績が大きく上がった（論文は2026年にOrganization Science誌に掲載）。

| 指標 | AIを使ったグループの変化 |
| --- | --- |
| 終えられた仕事の数 | 約12%増えた |
| 仕事の速さ | 約25%速くなった |
| 成果物の質（評価者の採点） | 約32%上がった（学術誌掲載版。2023年の作業論文では40%超） |

これだけを見ると、「戦略づくりも全部AIに任せればよい」と思えるかもしれない。ところが、実験には続きがある。

### 1.3 AIを使った方が間違えた実験（基礎）

同じ実験で、もう一つ別の種類の仕事も行われた。それは、企業の数字のデータと、社員へのインタビュー記録を組み合わせて、「どのブランドに投資すべきか」を判断する仕事である。一見もっともらしい答えがあるが、資料を丁寧に読み合わせると別の答えが正しいと分かるように作られていた。

| グループ | 正しい答えにたどり着いた割合 |
| --- | --- |
| AIを使わない | 84.5% |
| AIを使う | 70.6% |
| AIを使う（使い方の講習あり） | 60.0% |

AIを使った2つのグループは、使わないグループより平均で約19ポイントも正答率が低かった【要更新】。しかも、AIを使った人たちは、間違っていても説得力のある文章で答えを書く傾向があった。さらに驚くべきことに、使い方の講習を受けたグループの方が、さらに正答率が低かった。AIに慣れて信頼しすぎたためだと考えられている。

**【例】** カーナビに慣れたドライバーを思い浮かべるとよい。普段の道では、カーナビはとても便利である。しかし、工事中で通れない道を案内されたとき、カーナビを信じ切っている人ほど、目の前の看板に気づかずに進んでしまう。AIも同じで、便利さに慣れるほど、「その答えは本当か」と疑う力が弱くなりやすい。

### 1.4 大事なのは「どこで使うか」を見分けること（基礎）

1.2と1.3の実験から分かるのは、**AIは仕事の種類によって、効果がプラスにもマイナスにもなる**ということである。しかも、その境目は一見しただけでは分からない。どちらの仕事も「企画や分析」に見えるからである。

研究者たちは、この境目を「ジャグド・フロンティア（ギザギザの最前線）」と呼んだ。AIが得意な領域と苦手な領域の境目は、まっすぐな線ではなく、ギザギザに入り組んでいるという意味である。第4章で詳しく説明する。

【ポイント】戦略立案でAIを使うときに問うべきは「AIを使うかどうか」ではなく、「この仕事はフロンティアの内側か、外側か」である。

なお、この実験は一つの会社の、一つの時点（2023年）のAIを使ったものである。AIは年々性能が上がるので、今は得意な仕事が広がっている可能性がある。だからこそ、「12%」「19ポイント」といった数字そのものよりも、**仕事の種類によって効果の向きが変わる**という構造を覚えておくことが大切である。

### 1.5 中小企業にとっての意味【経営者の視点】

中小企業では、経営企画の専任担当者がいないことが多い。社長が一人で計画を考え、頭の中で結論を出すことも珍しくない。生成AIは、そうした会社にとって「壁打ちの相手」や「調べ物を手伝うスタッフ」になる。特に、社長の考えに反対意見を言いにくい会社では、AIに「この計画の弱点を指摘して」と頼む使い方が役に立つ（第3章）。ただし、自社の数字や取引先の事情を踏まえた「最後の判断」は、今までどおり経営者の仕事である。

## 2 基礎：戦略立案の道具をそろえる

**【この章のポイント】** AIを使う前に、戦略立案でよく使われる道具を知っておく。道具を知らないと、AIに何を頼めばよいかも、AIの答えが良いかどうかも判断できない。この章では、5つの道具をA社の例で説明する。

### 2.1 戦略とは「選ぶこと」である（基礎）

戦略という言葉は難しく聞こえるが、ひとことで言えば「限られたお金と人を、どこに使い、どこに使わないかを選ぶこと」である。すべての客に、すべての商品を、一番安く売ることはできない。だから選ぶ。

**【例】** 駅前のラーメン屋が、「昇安の定食を増やして会社員を取り込む」か、「夜の限定メニューで高単価の客を狙う」かを迷っているとする。両方やろうとすると、厨房も人手も足りなくなる。どちらかを選び、もう一方はやらないと決めることが戦略である。

AIは選択肢をたくさん出してくれるが、「どれを選び、どれを捨てるか」は決めてくれない。ここが、本書全体を通じた前提である。

### 2.2 SWOT分析：自社の強み・弱みと外の変化を整理する（基礎）

SWOT分析は、自社の状況を4つの箱に分けて整理する道具である。英語の頭文字を取ってSWOTと呼ぶ。

|  | よい影響 | 悪い影響 |
| --- | --- | --- |
| **社内（自分で変えられる）** | 強み（Strength） | 弱み（Weakness） |
| **社外（自分では変えられない）** | 機会（Opportunity） | 脅威（Threat） |

**【例】A社のSWOT**（本書の設定）

| 箱 | 内容 |
| --- | --- |
| 強み | 長年の取引先との信頼関係。部品の不具合や修理の記録を長年蓄積している |
| 弱み | 値引きに頼った営業で粗利率が低下。売掛金と在庫が膨らみ、借入金が増えている |
| 機会 | 取引先の工場で人手不足が進み、部品の故障を事前に知りたいという声が増えている |
| 脅威 | 海外の低価格品との競争。仕入価格の上昇 |

SWOTは便利だが、書いただけでは戦略にならない。大事なのは、「強みを生かして機会をつかむにはどうするか」「弱みが脅威と重なると何が起きるか」と、箱どうしを組み合わせて考えることである。A社なら、「蓄積した不具合の記録（強み）を生かして、故障を事前に知らせるサービス（機会）を始める」という方向が見えてくる。

### 2.3 5つの力：業界のもうけやすさを考える（基礎）

経営学者ポーターは、業界のもうけやすさを決める5つの力を示した。①同業者どうしの競争、②新しく参入してくる会社、③代わりになる商品（代替品）、④買い手（顧客）の交渉力、⑤売り手（仕入先）の交渉力、である。この力が強いほど、業界はもうかりにくい。

**【例】** A社の粗利率が下がったのは、④顧客の交渉力（大口の取引先からの値下げ要求）と、⑤仕入先の交渉力（仕入価格の値上げ）に挟まれたためと説明できる。この状況で「値引きして売上を増やす」と、さらに粗利率が下がる。

### 2.4 中期経営計画：3年後の姿とそこへの道すじ（基礎）

中期経営計画とは、およそ3年後の会社の姿と、そこに向かうための施策、数字の目標をまとめたものである。中期計画には、ふつう次の3つが入る。

1. **目指す姿**：どんな顧客に、どんな価値を届ける会社になるか。
2. **施策**：そのために何をするか。何をやめるか。
3. **数字の目標**：売上、利益、そして本講義ではROIC。

ここで大事なのは3の数字の目標である。売上だけを目標にすると、A社のように「値引きして売上を取りに行く」計画になりがちである。**事業に使っているお金100円あたり、年に何円稼ぐか**を表すROICを目標に入れると、「もうけの厚さ」と「お金の回りの速さ」の両方を考えた計画になる（第4巻）。

### 2.5 シナリオプランニング：未来を一つに決め打ちしない（基礎）

未来は誰にも分からない。そこで、「起こりうる未来」をいくつか用意して、どの未来になっても対応できるように計画を作る方法がある。これを「シナリオプランニング」という。石油会社のシェルが1970年代に使ったことでよく知られている。

**【例】** 遠足の計画を立てるとき、「晴れ、曇り、雨」の3つの天気を想定しておくとよい。晴れなら山に登る、曇りなら公園で遊ぶ、雨なら科学館に行く。どの天気でも必要なのは「弁当と水筒」、雨のときだけ必要なのは「傘と電車代」。天気を当てることではなく、どの天気でも困らない準備をすることが目的である。

会社の計画も同じである。シナリオプランニングでは、次のことをする。

1. 自社に大きく影響し、しかも先が読めない要因を選ぶ（A社なら「値下げ競争が続くか」「取引先が新しいサービスを求めるか」）。
2. その組み合わせから、互いに大きく違う3〜4つの未来を描く。
3. 未来ごとに、自社の数字（売上、利益、ROIC）がどうなるかを計算する。
4. どの未来でもやるべき施策と、特定の未来でだけやる施策を分ける。
5. 「どの未来に向かっているか」を知らせる数字（先行指標）を決めて、見張る。

これまでは、3つ以上の未来を描き、それぞれの数字を計算するのに手間がかかりすぎた。生成AIは、この手間を大きく減らす。ただし、計算そのものは表計算で行う（第4章）。

### 2.6 競合分析：相手を知る（基礎）

自社の戦略は、競合との比較なしには決められない。上場している競合なら、有価証券報告書（上場企業が毎年公開する決算や事業の説明書）が金融庁のEDINETで無料で見られる。競合の粗利率、売掛金の日数、力を入れている事業などを比べると、自社の立ち位置が分かる。

こうした資料は長くて読むのが大変だが、生成AIは「要点を抽き出して比べる」のが得意である。ただし、**数字は必ず元の資料で確かめる**。AIが数字を読み間違えたり、別の年度の数字を混ぜたりすることがあるからである。中小企業の競合で決算が公開されていない場合は、ウェブサイト、求人情報、展示会の出展内容などから動きを読み取る。

## 3 考え方：AIと人の協働

**【この章のポイント】** AIと一緒に戦略を考えるとき、人とAIの役割分担には大きく2つの型がある。「ケンタウロス型」と「サイボーグ型」である。また、AIを「反対意見を言う役」として使う方法と、AIを使うほど考えが似てしまうという落とし穴も知っておく。

### 3.1 ケンタウロス型とサイボーグ型（基礎）

第1章で紹介したBCGとハーバード大学などの実験では、AIを上手に使っていた人に2つの型が見られた。

| 型 | どう使うか | イメージ |
| --- | --- | --- |
| **ケンタウロス型** | 仕事を切り分け、「ここはAI、ここは人」と担当をはっきり分ける | ギリシャ神話の半人半馬。上半身（人）と下半身（馬）の境目がはっきりしている |
| **サイボーグ型** | 一つの作業の中で、人とAIが細かく何度もやり取りする | 体の中に機械が組み込まれている。どこまでが人でどこからが機械か、境目が細かい |

**【例】** 中期計画の「市場の見通し」の章を書く場面で考える。

- **ケンタウロス型**：統計資料の要約と表の作成はAIに任せる。その表を見て「どの未来に備えるか」を決め、文章を書くのは人が行う。
- **サイボーグ型**：人が一文書くとAIに「反論は？」と聞き、AIの答えを見て人が書き直し、AIにまた「数字の根拠は？」と聞く。これを細かく繰り返す。

**【ポイント】** どちらが正しいということはない。ケンタウロス型は「AIが苦手な部分」に人がしっかり責任を持てるので、ミスが少なく、新人にも教えやすい。サイボーグ型は速く深く考えられるが、AIの言葉に引っぱられやすい。准初級のうちは**ケンタウロス型から始め、慣れてきたらサイボーグ型を取り入れる**のがおすすめである。

### 3.2 AIを「反対役」にする：レッドチーム（基礎）

「レッドチーム」とは、もともと軍隊や情報セキュリティの言葉で、**わざと敵の立場に立って、自分たちの計画の弱点を探す役**のことである。会社の中では、計画を作った本人や部下は上司の計画に反対しにくい。そこでAIに反対役をさせる。

**【例】** A社が「故障を事前に知らせるサービスを始める」という計画を作ったとする。AIに次のように頼む。

> あなたは、A社の取引先である工場の購買部長です。この計画を読んで、「このサービスには、お金を払いたくない」と思う理由を5つ挙げてください。

AIは、「すでに機械メーカーが同じサービスを無料で付けている」「データを社外に出したくない」など、作った本人が気づきにくい反論を出してくる。反論が全部正しいわけではないが、**計画を厳しい目で見直すきっかけ**になる。

**【経営者の視点】** 中小企業の社長の周りには、反対意見を言える人が少ないことが多い。AIのレッドチームは「遠慮しない相談相手」になる。ただし、AIの反論を見て安心してしまうのは逆効果である。「AIが出した反論に、一つずつ答えを用意できるか」まで確かめて、初めて意味がある。

### 3.3 アイデアが似てくる落とし穴（基礎）

AIを使うと、一人ひとりのアイデアの質は上がりやすい。一方で、**みんなが同じAIを使うと、アイデアが似通ってくる**という研究結果がある。BCGの実験でも、AIを使ったグループは一人ひとりのアイデアの質が上がった一方で、グループ全体で見たアイデアのばらつきは小さくなったと報告されている【要更新】。

**【例】** 10社が同じAIに「中小部品商社の新しい事業を考えて」と聞くと、10社とも「予知保全サービス」「ECサイト」「サブスクリプション」のように、似た答えが返ってきやすい。全員が同じ方向に進めば、そこは激しい競争の場になる。

戦略の本質は「他社と違うこと」を選ぶことである（2.1節）。だから、AIのアイデアは**出発点**として使い、自社だけが持っている情報（A社なら長年の不具合記録、取引先との関係）を加えて、他社にはまねできない形に変えていく必要がある。

**【ポイント】** アイデアが似てくるのを防ぐ工夫として、次のようなものがある。

1. AIに聞く前に、まず自分たちで考えを書き出す（AIの答えに引っぱられないため）。
2. AIに自社だけの情報を渡し、「これを生かした案」を求める。
3. AIに「よくある案を除いて」「業界の常識に反する案を」と頼む。
4. 複数の人が別々にAIを使い、結果を持ち寄って比べる。

### 3.4 戦略の流れの中でのAIの役割（応用）

戦略づくりは、「情報を集める → 考える → 決める → 実行する → 振り返る」の繰り返しである。それぞれの段階で、AIが手伝いやすい部分と、人がやるべき部分は違う。

| 段階 | AIが手伝いやすいこと | 人がやるべきこと |
| --- | --- | --- |
| 情報を集める | 資料の要約、競合の比較表 | 元資料で数字を確かめる |
| 考える | シナリオの案、反対意見 | 自社だけの情報を加える |
| 決める | 選択肢ごとの数字の整理 | **どれを選び、何を捨てるかを決める** |
| 実行する | 進み具合の報告書の下書き | 現場を動かす、人を説得する |
| 振り返る | 計画と実績の差の説明案 | 次に何を変えるかを決める |

表を見ると分かるように、「決める」の欄は人の仕事である。AIの役割は、**決める人がより良い材料で決められるようにすること**である。

## 4 ジャグド・フロンティアとシナリオ計画（詳説）

**【この章のポイント】** この巻の中心となる章である。前半では「ジャグド・フロンティア」（AIが得意な仕事と苦手な仕事の、ギザギザの境界）を図で詳しく説明する。後半では、A社の中期計画を3つのシナリオで作り、ROICで比べる。AIを「境界の内側」で使い、計算と判断は人と表計算が受け持つという分担を、具体的な数字で体験する。

### 4.1 ジャグド・フロンティアとは（基礎）

「ジャグド（jagged）」は英語で「ギザギザの」、「フロンティア」は「境界線」という意味である。AIが上手にこなせる仕事と、こなせない仕事の境目は、まっすぐな線ではなくギザギザになっている。これが「ジャグド・フロンティア」という考え方である。

![ジャグド・フロンティアの概念図 · 境界の内側と外側の仕事](/images/guidebook/vol08-fig1.png)

*ジャグド・フロンティアの概念図 · 境界の内側と外側の仕事*

図の読み方は次のとおりである。

- **縦の軸**は、人から見たときの仕事の難しさである。上ほど難しい。
- **色のついた部分**が境界の内側で、AIが得意な仕事である。ここでAIを使うと、品質も速さも上がる。
- **色のない部分**が境界の外側で、AIが苦手な仕事である。ここでAIの答えをうのみにすると、かえって正答率が下がる。
- **ギザギザの線**が境界である。境界の高さが場所によって大きく違う点に注目してほしい。

いちばん大事なのは、図の真ん中の「数表の突き合わせ」である。人から見ると「反対意見の列挙」や「シナリオ案の文章化」より易しく見える。それなのに、境界のくぼみに落ちていて、AIが苦手な側にある。

**【例】** 料理にたとえると分かりやすい。プロ並みのフランス料理を作れる人が、なぜか目玉焼きの焼き加減だけは苦手、ということがある。「難しい料理ができるのだから、簡単な料理もできるはず」と思って任せると失敗する。AIも同じで、**難しさの順番と、AIの得意・不得意の順番は一致しない**。

**【ポイント】** 「この仕事は簡単だからAIに任せてよい」という判断は危ない。仕事の難しさではなく、「その仕事が境界の内側にあるか」で判断する必要がある。

### 4.2 実験の数字を読む（基礎）

この考え方は、BCG（ボストン・コンサルティング・グループ）とハーバード大学などの研究者が行った実験から生まれた。概要は次のとおりである【要更新】。

| 項目 | 内容 |
| --- | --- |
| 時期と対象 | 2023年、BCGのコンサルタント758人 |
| 使ったAI | GPT-4 |
| 境界の内側の仕事（新商品のアイデア出しなど） | AIを使った人は、こなした仕事の量が12.2%多く、速さが25.1%速く、品質は約32%高かった（作業論文では40%超） |
| 境界の外側の仕事（数表と聞き取りメモを突き合わせて答えを出す問題） | AIを使わない人の正答率84.5%に対し、AIを使った2つのグループは70.6%と60.0%。平均でおよそ19ポイント低かった |

境界の外側の仕事では、AIはもっともらしい説明つきで間違った答えを出した。そして、多くの人がその答えをそのまま受け入れてしまった。**AIの間違いは「自信がありそうな顔」でやってくる**のである。

**【要更新】** この実験は、1社のコンサルタントを対象に、2023年時点のAIで行われたものである。AIの性能は年々上がっており、境界の位置は動いている。数字はそのまま覚えるのではなく、「境界はギザギザで、しかも動く」という考え方を持ち帰ってほしい。

### 4.3 境界の内か外かを見分ける5つの問い（応用）

境界は目に見えない。しかも動く。そこで、仕事をAIに任せる前に、次の5つを自分に問いかけるとよい。

1. **答えを確かめる方法があるか**：元の資料や計算で確かめられる仕事は、AIに任せても間違いに気づける。
2. **AIが知らない情報が必要か**：社内の事情、取引先との関係、公開されていない数字が必要なら、境界の外になりやすい。
3. **細かい数字の計算や突き合わせがあるか**：数表を読み比べたり、合計を合わせたりする作業は、意外と境界の外にある。計算は表計算に任せる。
4. **間違えたときの損害は大きいか**：損害が大きい仕事ほど、境界の内側でも人が必ず確認する。
5. **似た仕事で試したことがあるか**：自社の仕事で一度試し、うまくいった仕事とそうでない仕事を記録していくと、自社なりの「境界の地図」ができる。

**【経営者の視点】** 境界の地図は会社ごとに違う。同じAIでも、使う人の腕や渡す情報によって結果が変わるからである。社長は「AIを使え」と号令をかけるだけでなく、「どの仕事でうまくいき、どの仕事で失敗したか」を社内で共有する仕組みを作るとよい。これが、他社にはまねできない自社の財産になる。

### 4.4 A社の3シナリオ中期計画（応用）

ここからは、第2章で学んだシナリオプランニングを、A社に当てはめる。A社の2026年度の実績（第4巻）は、売上30.0億円、粗利率21%、ROIC4.4%であった。資本コスト（お金を出してくれた人が期待する利回り）は6%なので、ROICがそれを下回り、**価値を減らしている状態**である。

3年後に向けて、次の3つのシナリオを考えた（すべて本書の架空の設定）。

| シナリオ | どんな未来か | 主な前提 |
| --- | --- | --- |
| S1 値引き競争が続く | 今の延長。値引きで売上を取りに行く | 売上31.5億円、粗利率20%、販管費5.4億円、売掛金90日・在庫75日のまま |
| S2 改善施策をやり切る | 値引きをやめ、売掛金と在庫を減らす | 売上32.0億円、粗利率22.5%、販管費5.4億円、売掛金70日・在庫60日 |
| S3 高付加価値へ転換 | 故障を事前に知らせるサービスを始める | 売上34.0億円、粗利率24%、販管費5.8億円、売掛金65日・在庫55日、設備を1.0億円追加 |

この前提で計算すると、次のようになる（単位：億円。税率30%、資本コスト6%で計算）。

|  | 2026年度実績 | S1 値引き競争 | S2 改善やり切り | S3 高付加価値 |
| --- | --- | --- | --- | --- |
| 営業利益 | 1.10 | 0.90 | 1.80 | 2.36 |
| 税引後営業利益（NOPAT） | 0.77 | 0.63 | 1.26 | 1.65 |
| 投下資本（事業に使っているお金） | 17.52 | 17.99 | 15.32 | 15.91 |
| 利益の厚さ（NOPAT÷売上） | 2.6% | 2.0% | 3.9% | 4.9% |
| お金の回る速さ（売上÷投下資本） | 1.71回 | 1.75回 | 2.09回 | 2.14回 |
| **ROIC** | **4.4%** | **3.5%** | **8.2%** | **10.4%** |
| EVA（価値を増やした額） | −0.28 | −0.45 | +0.34 | +0.70 |

### 4.5 表の読み方の手順（応用）

表は次の順番で読むとよい。

1. **ROICと資本コスト6%を比べる**：S1は3.5%で6%を下回り、価値を減らし続ける。S2とS3は6%を上回り、価値を生む。
2. **ROICを「利益の厚さ×お金の回る速さ」に分ける**（第4巻のROICツリー）：S2は8.2% ≒ 3.9% × 2.09回、S3は10.4% ≒ 4.9% × 2.14回である。
3. **なぜそうなったかを確かめる**：S1は売上が1.5億円増えるのに、粗利は6.3億円のまま増えない（31.5 × 20% = 6.3）。販管費だけが増えるので、営業利益は減る。売上が増えた分だけ売掛金と在庫も膨らみ、投下資本も増える。<strong>「売上を増やしたのに会社の価値が減る」</strong>典型である。
4. **どのシナリオでもやる施策を探す**：S2とS3の両方に「売掛金と在庫を減らす」が入っている。これは、どの未来になってもやるべき施策である。一方、「新サービスへの設備投資」はS3でだけ必要で、「取引先が本当にお金を払うか」を確かめてから決める施策である。
5. **先行指標を決める**：「取引先からの予知保全の問い合わせ件数」が増えてきたら、S3に向かっている合図と考える。「値下げ要求の件数」が増えたら、S1の方向に引っ張られている合図である。

**【ポイント】** シナリオは「当てる」ためのものではない。**どの未来でもやること**と、**特定の未来でだけやること**を分けるための道具である。

### 4.6 この作業のどこでAIを使うか（応用）

4.4と4.5の作業を、ジャグド・フロンティアに当てはめると次のようになる。

| 作業 | 境界の内か外か | 分担 |
| --- | --- | --- |
| 先が読めない要因を挙げる | 内側 | AIに10〜20個挙げさせ、人が絞る |
| 3つの未来の物語を書く | 内側 | AIに下書きさせ、人が自社の事情を加える |
| 未来ごとの前提の数字を決める | 外側になりやすい | 人が過去の実績や取引先の声から決める |
| ROICやEVAを計算する | 外側（AIの暗算は間違えやすい） | 表計算で計算する。AIに計算式を作らせるのはよい |
| 計画の弱点を探す | 内側 | AIにレッドチームをさせる（3.2節） |
| どのシナリオに備えるか決める | 外側 | 経営者が決める |

**【技術ノート】** 最近の生成AIには、自分でプログラムを書いて計算する機能を持つものがある。この機能を使えば計算の正確さは上がる。ただし、**前提の数字が正しいか、計算式が正しいか**は人が確かめる必要がある。ROIC＝NOPAT÷投下資本のように、本書の式と同じ式で計算しているかを必ず見る。

### 4.7 よくある質問（基礎）

- **Q：シナリオはいくつ作ればよいか。** A：3つか4つがよい。2つだと「良い未来と悪い未来」になりがちで、真ん中の未来を考えなくなる。5つ以上だと覚えきれない。
- **Q：AIが作ったシナリオをそのまま使ってよいか。** A：物語の下書きとしてはよいが、前提の数字は必ず自社のデータで決める。AIは自社の売掛金の日数を知らない。
- **Q：小さな会社でもシナリオプランニングは必要か。** A：必要である。小さな会社ほど、一つの取引先や一つの商品に頼っていることが多く、外の変化の影響を大きく受ける。表計算とAIを使えば、半日ほどで3シナリオを作ることも難しくない。

## 5 AI活用の型

**【この章のポイント】** 企画・戦略の仕事でAIを使う場面を、本講義の「3本の柱」に沿って整理する。あわせて、AIの種類の選び方と、効果を測る指標を確認する。

### 5.1 3本柱別のユースケース（基礎）

本講義では、AI活用を①意思決定の高度化・高速化、②業務プロセスの自律化、③新規事業創出、の3本の柱で整理している（第1巻）。企画・戦略の仕事に当てはめると次のようになる。

| 柱 | 企画・戦略でのユースケース | 動く指標 |
| --- | --- | --- |
| ① 意思決定の高度化・高速化 | シナリオの下書き、計画へのレッドチーム、競合の比較表、投資案ごとのROICの比較 | 計画策定にかかる日数、検討した選択肢の数、計画と実績のずれ |
| ② 業務プロセスの自律化 | 業界ニュースや競合の公開情報の定期的な収集と要約、会議資料の下書き、先行指標の自動集計と通知 | 情報収集にかかる時間、会議の準備時間 |
| ③ 新規事業創出 | 新しい事業アイデアの幅出し、顧客の声の整理、事業計画書の下書き | 検討した事業案の数、試験的に始めた事業の数、新規売上 |

**【例】A社の場合**

- **①**：中期計画の3シナリオを作り、AIにレッドチームをさせてから取締役会で議論する（第4章）。
- **②**：毎週月曜日に、主要な取引先と競合のニュースをAIが要約して経営陣に届ける。「値下げ要求の件数」などの先行指標もあわせて報告する。
- **③**：蓄積した不具合の記録を生かした「故障を事前に知らせるサービス」の事業計画を、AIと一緒に下書きする。ただし、取引先に実際に話を聞きに行くのは人である。

### 5.2 AIの種類を選ぶ（基礎）

「AI」と一口に言っても、得意な仕事は種類によって違う。企画・戦略の仕事では、次のように使い分ける。

| 課題 | 適した道具 | 理由 |
| --- | --- | --- |
| 将来の売上の見込みを出す | 予測AI、または表計算 | 過去のデータから数字を出す仕事。毎回同じ結果が出る仕組みがよい |
| 未来の物語をいくつも書く | 生成AI | 言葉で選択肢を広げる仕事。境界の内側 |
| シナリオごとのROICを計算する | 表計算 | 数字の計算。生成AIの暗算に任せない |
| 競合の情報を定期的に集める | AIエージェント（人が結果を確認） | 検索、要約、保存など複数の手順を伴う仕事 |

**【技術ノート】** AIエージェントとは、目標を与えると、検索や資料の作成などいくつもの手順を自分で進めるAIのことである。便利だが、関係のないサイトの情報を混ぜたり、古い情報を使ったりすることがある。戦略の材料に使うときは、**出典と日付を必ず一緒に出させる**。

### 5.3 効果をROICツリーにつなぐ（応用）

企画・戦略の仕事でAIを使っても、「資料が早くできた」だけでは会社の価値は増えない。効果は、**より良い決定を通じて、ROICツリーのどこかが動くこと**で現れる。

**【例】** A社の場合、シナリオ計画によって「値引きで売上を取りに行く」方針をやめたとする。すると、粗利率が上がり、売掛金と在庫が減り、ROICが4.4%から8.2%に向かう（S2）。AIはこの決定の「材料」を作っただけだが、材料がなければ値引きを続けていたかもしれない。

**【ポイント】** 企画・戦略でのAIの効果は、直接は測りにくい。そこで、「検討した選択肢の数」「計画にかかった日数」のような**過程の指標**と、ROICやEVAのような**結果の指標**の両方を記録しておくとよい。

## 6 実務の手順

**【この章のポイント】** 第4章の3シナリオ計画を、実際にAIを使って作る手順を6ステップで示す。各ステップに、AIへの頼み方（プロンプト）の例と、結果を確かめるポイントをつけた。

![AIを使ったシナリオ計画 · 6ステップと担い手](/images/guidebook/vol08-fig2.png)

*AIを使ったシナリオ計画 · 6ステップと担い手*

図の右側は、そのステップの主な担い手である。AIが入るのはステップ2・3・5で、いずれもジャグド・フロンティアの内側の仕事（言葉で選択肢を広げる仕事）である。始めと終わり（ステップ1と6）は必ず人が担う。

### 6.1 ステップ1：問いを決める（基礎）

最初に、経営者が「何に備えるための計画か」を決める。A社なら「3年後に、ROICを資本コスト6%以上に戻すには、何をすべきか」である。問いがぼやけていると、AIの答えもぼやける。

### 6.2 ステップ2：要因を洗い出す（基礎）

**プロンプトの例**

> あなたは中小企業の経営を支援する専門家です。当社は、工場向けに機械部品を売る商社で、年間売上は約30億円です。今後3年間に当社の業績に大きく影響し、しかも先が読みにくい要因を、15個挙げてください。それぞれについて、「影響の大きさ」と「先の読めなさ」を高・中・低で示してください。

**確かめるポイント**

- 自社にとって本当に影響が大きいか。AIは一般論を並べがちである。
- 「先が読める」もの（人口減少など）が混じっていないか。先が読めるものは、すべてのシナリオの前提に入れる。
- 最後に、影響が大きく、先が読めない要因を**人が2つに絞る**。A社は「値下げ競争が続くか」と「取引先が新しいサービスを求めるか」を選んだ。

**【注意】** プロンプトには、取引先の社名や個人名、社外秘の数字をそのまま入れない。必要なら「取引先X」のように置き換える（第8章）。

### 6.3 ステップ3：未来の物語を書く（基礎）

**プロンプトの例**

> 次の2つの要因を使って、3年後の未来を3つ書いてください。要因A：値下げ競争が続くか。要因B：取引先が故障を事前に知るサービスを求めるか。それぞれの未来に、短い名前をつけ、「その未来では何が起きているか」を200字程度で書いてください。数字は書かないでください。

**確かめるポイント**

- 3つの未来が、互いに十分に違うか。「少し良い」「少し悪い」だけでは役に立たない。
- 自社だけの事情（蓄積した不具合記録、取引先との関係）を、人が書き加えたか。
- 「数字は書かないで」と頼んだのは、AIがもっともらしい数字を作ってしまうのを防ぐためである。

### 6.4 ステップ4：数字に直す（応用）

ここは境界の外側になりやすいステップである。次のように分担する。

1. **前提の数字は人が決める**：売上、粗利率、販管費、売掛金の日数、在庫の日数、設備の額。過去3年の実績と、取引先や営業の声をもとに決める。
2. **計算は表計算で行う**：第4巻のROICツリーの式をそのまま使う。AIに「この式を表計算の式に直して」と頼むのはよい。
3. **検算する**：「利益の厚さ×お金の回る速さ＝ROIC」が成り立つかを確かめる。A社のS2なら、3.9% × 2.09回 ≒ 8.2%である。

### 6.5 ステップ5：弱点を探す（応用）

**プロンプトの例（レッドチーム）**

> あなたは、この会社の計画に反対する立場の取締役です。添付の3シナリオ計画を読んで、①前提が楽観的すぎる点、②見落としているリスク、③競合が取りそうな対抗策を、それぞれ3つずつ指摘してください。遠慮せず、厳しく指摘してください。

**確かめるポイント**

- 指摘の一つひとつに、「受け入れて計画を直す」「反論できる」「分からないので調べる」のどれかを書き込む。
- 「AIが反論しなかったから大丈夫」とは考えない。AIが知らない自社の事情については、反論も出てこない。

### 6.6 ステップ6：決めて見張る（基礎）

最後に、経営者が次の3つを決めて、記録に残す。

1. **どの未来でもやる施策**（A社なら、売掛金と在庫を減らす）
2. **特定の未来でだけやる施策と、その合図**（A社なら、問い合わせが一定数を超えたら新サービスに設備投資する）
3. **見張る先行指標と、見直しの時期**（四半期ごとなど）

**【経営者の視点】** この6ステップは、一度で完成させるものではない。最初は半日で荒い版を作り、取締役会や幹部会で議論して、四半期ごとに前提を直していく。AIのおかげで、この「作り直し」の手間が小さくなったことが、実は一番大きな変化である。

## 7 ケーススタディ

**【この章のポイント】** 3つの事例で、ここまでの考え方を確かめる。ケース7.1は公開された研究、ケース7.2と7.3は講義のために作った架空の事例である。各ケースは「状況」「何が起きたか」「学び」「考えてみよう」の順に読む。

### 7.1 ケース：コンサルタント758人の実験（基礎）

**状況**：2023年、BCGのコンサルタント758人が、GPT-4を使うグループと使わないグループに分かれて、実際の仕事に近い課題に取り組んだ。課題には、AIが得意なもの（新商品のアイデア出しなど）と、苦手なもの（数表と聞き取りメモを突き合わせる問題）が含まれていた【要更新】。

**何が起きたか**：AIが得意な課題では、AIを使った人の成果が大きく上がった。一方、苦手な課題では、AIを使った人のほうが正答率が低かった（4.2節の表）。多くの人が、AIのもっともらしい説明をそのまま受け入れたためである。一方で、ケンタウロス型やサイボーグ型のように、AIとの分担を意識していた人たちもいた（第3章）。

**学び**

- 優秀な人でも、AIの答えをうのみにする。「優秀な社員が使うから大丈夫」とは言えない。
- 問題はAIの性能だけでなく、**人が境界の位置を知らないこと**にある。

**考えてみよう**：あなたの職場で、「数表と聞き取りを突き合わせる」のに似た仕事はどれか。

### 7.2 ケース：社内アイデアコンテストで案がそろった（架空）

**状況**：ある地方の食品メーカー（従業員120人）が、新規事業の社内アイデアコンテストを開いた。「AIを自由に使ってよい」としたところ、前年の3倍の40件が集まった。

**何が起きたか**：審査してみると、40件のうち半分以上が「健康志向のサブスクリプション」「ネット通販の強化」「食品ロスの削減」のどれかだった。どれも文章はよくできていたが、他社でも思いつく内容だった。受賞したのは、工場のベテラン社員が出した「自社でしか作れない発酵食品を、地元の旅館と組んで朝食に出す」という案であった。この社員は、まず自分で考えを書き出し、AIは「反対意見を出させる」ためにだけ使っていた。

**学び**

- AIは「質の底上げ」には効くが、そのままだと案が似てくる（3.3節）。
- 他社と違う案は、<strong>自社だけが持つもの（技術、関係、現場の知恵）</strong>から生まれる。

**考えてみよう**：あなたが審査員なら、次回のコンテストのルールをどう変えるか。

### 7.3 ケース：A社、競合比較表の数字違い（架空）

**状況**：A社の経営企画担当は、中期計画の資料として、上場している競合3社の比較表をAIに作らせた。「粗利率」「売掛金の日数」「在庫の日数」を並べたきれいな表が、数分でできた。

**何が起きたか**：取締役会の前日、経理部長が元の有価証券報告書と照らし合わせたところ、1社分の数字が1年前のものだった。また、「売掛金の日数」の計算の仕方が、A社の計算方法（売掛金÷売上×365）と違っていた。そのまま出していれば、「競合は売掛金の回収が速い」という誤った結論で議論が進むところだった。

**学び**

- 要約や表の形に整える仕事は境界の内側だが、**数字の年度や計算方法をそろえる仕事は外側**になりやすい。
- 「数字は必ず元の資料で確かめる」（2.6節）を、手順として決めておく必要がある。

**考えてみよう**：この間違いを防ぐには、AIへの頼み方をどう変えればよかったか。（ヒント：年度、計算式、出典のページを表に入れさせる）

## 8 ガバナンスとリスク

**【この章のポイント】** 戦略の仕事でAIを使うときのルールを決める。大事なのは、①誰が決めるか、②情報の出どころを確かめるか、③なぜそう決めたかを記録に残すか、④秘密を守れるか、の4つである。

### 8.1 決めるのは人である（基礎）

AIがどれだけ良い案を出しても、結果に責任を持つのは経営者である。取締役会で「AIがそう言ったから」は説明にならない。会社法でも、取締役には会社のために忠実に仕事をする義務がある。AIを使ったことは、その義務を軽くしない。

**【ポイント】** よい使い方は、「AIを使って、より多くの選択肢と反対意見を検討したうえで、人が決めた」と説明できる状態である。

### 8.2 出どころを確かめる（基礎）

AIが出した情報を戦略の材料に使うときは、次の3つを確かめる。

| 確かめること | 例 |
| --- | --- |
| 出典 | どの資料のどのページか。出典が示せない情報は使わない |
| 日付 | いつの情報か。年度がそろっているか（ケース7.3） |
| 定義 | 「売掛金の日数」など、計算方法が自社と同じか |

特に、AIは存在しない資料や数字をもっともらしく作ってしまうことがある（これを「ハルシネーション」という）。戦略の資料に入れる数字は、**人が元の資料を開いて確かめたものだけ**にする。

### 8.3 判断の理由を記録に残す（応用）

戦略の決定は、後から振り返られる。そのときに、「何を前提に、どんな選択肢を比べ、なぜそれを選んだか」が分かるようにしておく。AIを使った場合は、次も残す。

- AIに頼んだ内容（プロンプト）と、使ったAIの名前、日付
- AIの答えのうち、採用したものと採用しなかったもの
- レッドチームの指摘と、それへの答え

**【例】** A社は、取締役会の資料に「AI活用の記録」という半ページの欄を設けた。そこに「シナリオの下書きと反対意見の洗い出しにAIを使った。数字はすべて表計算で計算し、経理部が確認した」と書く。この一文があるだけで、資料を読む人の安心感が変わる。

### 8.4 秘密を守る（基礎）

戦略の情報は、会社の中でも特に秘密性が高い。まだ発表していない事業計画、取引先ごとの利益、M&A（会社の買収）の検討などである。

- 会社が認めたAIサービス（入力した情報が学習に使われない契約のもの）だけを使う。
- 取引先の社名や個人名は、「取引先X」のように置き換えてから入力する。
- 上場企業の場合、未公開の重要な情報（インサイダー情報）の扱いには特に注意する。

**【要更新】** AIサービスの利用規約や、国のガイドライン（AI事業者ガイドラインなど）は、頻繁に変わる。講義の前に最新版を確かめる。

### 8.5 チェックリスト（基礎）

戦略資料を出す前に、次の5つを確かめる。

1. 数字はすべて、人が元の資料で確かめたか。
2. 計算は表計算などで行い、検算したか。
3. 自社だけの情報を加えて、他社と同じ案になっていないか。
4. 反対意見を検討し、答えを用意したか。
5. 秘密の情報を、認められていないAIに入力していないか。

## 9 演習ワークシート

A社の数字は第4巻の「付録データ：A社」と本巻の第4章による（単位：億円、税率30%、資本コスト6%）。各シートは「やり方」と「記入例」を示している。受講生は、自社または小規模版（B社）で同じ表を埋める。

### シート1：3シナリオ中期計画

**やり方**

1. 影響が大きく先が読めない要因を2つ選び、3つの未来に名前をつける（AIで下書きしてよい）。
2. 未来ごとに、売上・粗利率・販管費・売掛金の日数・在庫の日数・固定資産の前提を**自分で**決める。
3. 表計算でNOPAT、投下資本、ROIC、EVAを計算する（買掛金は売上原価の50日分とする）。
4. 「利益の厚さ×お金の回る速さ＝ROIC」で検算する。
5. 下の欄に、どの未来でもやる施策、特定の未来でだけやる施策、先行指標を書く。

**記入例（A社）**

| 項目 | 2026実績 | S1 値引き競争 | S2 改善やり切り | S3 高付加価値 |
| --- | --- | --- | --- | --- |
| 売上高 | 30.0 | 31.5 | 32.0 | 34.0 |
| 粗利率 | 21.0% | 20.0% | 22.5% | 24.0% |
| 販管費 | 5.2 | 5.4 | 5.4 | 5.8 |
| 売掛金の日数 / 在庫の日数 | 90日 / 75日 | 90日 / 75日 | 70日 / 60日 | 65日 / 55日 |
| 固定資産 | 8.5 | 8.5 | 8.5 | 9.5 |
| NOPAT | 0.77 | 0.63 | 1.26 | 1.65 |
| 運転資本（売掛金＋在庫−買掛金） | 9.02 | 9.49 | 6.82 | 6.41 |
| 投下資本 | 17.52 | 17.99 | 15.32 | 15.91 |
| ROIC | 4.4% | 3.5% | 8.2% | 10.4% |
| EVA | −0.28 | −0.45 | +0.34 | +0.70 |

| 欄 | 記入例 |
| --- | --- |
| どの未来でもやる施策 | 値引きの承認ルールを厳しくする。売掛金の回収と在庫の削減に取り組む |
| 特定の未来でだけやる施策 | S3：故障を事前に知らせるサービスに設備を1.0億円投資する（試験導入で取引先の反応を確かめてから） |
| 先行指標 | 値下げ要求の件数（S1の合図）、予知保全の問い合わせ件数（S3の合図） |

### シート2：AIあり・なしの比較

**やり方**

1. 戦略づくりの作業を4つ選ぶ。
2. 同じ作業を、AIなしとAIありの両方で行い、かかった時間と結果の質を記録する（グループで分担してよい）。
3. 結果を見て、その作業が境界の内側か外側かを判定する。
4. 「気づき」の欄に、自社の「境界の地図」に書き足すことを書く。

**記入例（A社、時間は架空の例）**

| 作業 | AIなし | AIあり | 判定 | 気づき |
| --- | --- | --- | --- | --- |
| 先が読めない要因の洗い出し | 2時間、8個 | 20分、15個 | 内側 | 自社に関係の薄い一般論が半分。絞り込みは人が必要 |
| 3つの未来の文章化 | 3時間 | 40分 | 内側 | 下書きは十分。取引先の事情は人が加筆 |
| 競合の比較表づくり | 4時間 | 30分＋確認1時間 | 一部外側 | 年度と計算式のずれがあった（ケース7.3） |
| シナリオごとのROIC計算 | 表計算で1時間 | AIの暗算は誤りあり | 外側 | 計算は表計算。AIには式の作成だけ頼む |

### シート3：レッドチーム・レビュー表

**やり方**

1. シート1の計画をAIに渡し、6.5節のプロンプトで反対意見を出させる。
2. 指摘を一つずつ表に写し、「受け入れる」「反論できる」「調べる」に分類する。
3. 対応を書き、計画を直した場合はその内容も書く。
4. 最後に、AIが出さなかった反論を自分たちで一つ以上足す。

**記入例（A社）**

| AIの指摘 | 分類 | 対応 |
| --- | --- | --- |
| S2で値引きをやめると、大口の取引先を失うおそれがある | 受け入れる | 取引先ごとの粗利を調べ、赤字の取引だけ条件を見直す方針に変える |
| S3の新サービスは、機械メーカーが無料で提供している | 調べる | 主要取引先3社に話を聞き、メーカーのサービスとの違いを確かめる |
| 売掛金を短くすると売上が落ちる | 反論できる | 支払い条件は新規取引から変える。既存取引は延滞分の回収から始める |
| （自分たちで足した反論）新サービスを担う人材が社内にいない | 受け入れる | 技術担当の採用・育成の計画をS3の施策に加える |

## 10 最終課題とのつながり

最終課題は「自社（または模擬企業）のAX Transformation Blueprint（AX計画書）」である。本巻の成果物は、その中の<strong>「戦略仮説」</strong>の部分になる。戦略仮説とは、「こういう未来が来るなら、こう勝つ。その結果、ROICはこう動く」という、後から確かめられる形の計画の芯である。

| 本巻の成果物 | 最終課題での使い方 |
| --- | --- |
| シート1：3シナリオ中期計画 | 計画書の「戦略仮説」。どの未来でもやる施策と、特定の未来でだけやる施策を分けて示す |
| シート2：AIあり・なしの比較 | 計画書の「AI活用の範囲」。自社の境界の地図を根拠に、どこでAIを使い、どこで使わないかを書く |
| シート3：レッドチーム・レビュー表 | 計画書の「リスクと対応」。主な反対意見とその答えを添える |
| 先行指標 | 計画書の「効果測定」。第4巻のKPI辞書に加える |

**提出物（中間チェック）**：第8回の後、シート1とシート3をA4で1枚にまとめて提出する。自社の数字を出せない場合は、小規模版（B社）または公開企業の有価証券報告書を使ってよい。

**評価の観点**

- 3つの未来が互いに十分に違い、自社にとって意味があるか。
- 前提の数字に根拠があり、ROICが正しく計算され、検算されているか。
- AIの使い方が、境界の内側と外側を意識したものになっているか。
- 自社だけの強みが生かされ、他社と同じ案になっていないか。

## 11 確認テストと討論課題

### 11.1 確認テスト（解答は末尾）

1. 「ジャグド・フロンティア」とは何か。仕事の「難しさ」との関係に触れて説明せよ。
2. BCGなどの実験で、境界の外側の仕事にAIを使った人の正答率はどうなったか。また、その主な理由は何か。
3. 「ケンタウロス型」と「サイボーグ型」の違いを説明せよ。
4. 「レッドチーム」とは何か。AIにレッドチームをさせるときの注意点を1つ挙げよ。
5. みんなが同じAIを使うと起きやすい問題は何か。それを防ぐ工夫を2つ挙げよ。
6. シナリオプランニングの目的は何か。「未来を当てること」との違いを答えよ。
7. A社のシナリオS1では、売上が増えるのにROICが4.4%から3.5%に下がる。その理由を数字を使って説明せよ。
8. A社のシナリオS2のROIC 8.2%を、「利益の厚さ」と「お金の回る速さ」に分けよ。
9. 戦略の決定にAIを使ったとき、記録に残すべきことを3つ挙げよ。

### 11.2 討論課題

1. ある社長は「AIが出した戦略案のほうが、企画部の案よりよくできている。企画部は小さくしてよい」と言う。賛成・反対の両方の立場で議論せよ。
2. AIの性能が上がると、境界の位置も動く。自社の「境界の地図」を、誰が、どのくらいの頻度で、どう更新すればよいか。
3. 同業他社がみな同じAIで戦略を立てる時代に、中小企業は何で差をつけるべきか。自社（または身近な会社）を例に考えよ。

### 11.3 確認テストの解答例

1. AIが得意な仕事と苦手な仕事の境界が、まっすぐではなくギザギザになっていること。人から見てやさしい仕事でも境界の外にあることがあり、難しさの順番とAIの得意・不得意の順番は一致しない。
2. AIを使わない人の正答率84.5%に対し、AIを使った2つのグループは70.6%と60.0%で、平均でおよそ19ポイント低かった。AIがもっともらしい説明つきで誤った答えを出し、人がそれをうのみにしたため。
3. ケンタウロス型は仕事を切り分けて、AIの担当と人の担当をはっきり分ける。サイボーグ型は一つの作業の中で、人とAIが細かく何度もやり取りする。
4. わざと反対の立場に立って、計画の弱点を探す役。注意点の例：AIが反論しなかったから大丈夫とは考えない（AIは自社の事情を知らない）。指摘ごとに答えを用意する。
5. アイデアが似通ってくる。工夫の例：AIに聞く前に自分で考えを書き出す。自社だけの情報を渡して案を求める。「よくある案を除いて」と頼む。複数の人が別々に使って比べる。
6. どの未来になっても困らないように備えること。未来を一つに決め打ちせず、どの未来でもやる施策と特定の未来でだけやる施策を分け、先行指標で向かう方向を見張る。
7. 売上は31.5億円に増えるが、粗利率が20%に下がるので粗利は6.3億円のまま増えない。販管費が5.4億円に増えるので、営業利益は1.10億円から0.90億円、NOPATは0.77億円から0.63億円に減る。一方、売掛金と在庫が膨らんで投下資本は17.52億円から17.99億円に増える。分子が減り分母が増えるので、ROICは0.63÷17.99≒3.5%に下がる。
8. 利益の厚さ＝1.26÷32.0≒3.9%、お金の回る速さ＝32.0÷15.32≒2.09回。掛け合わせると約8.2%。
9. AIに頼んだ内容と使ったAI・日付。AIの答えのうち採用したものとしなかったもの。レッドチームの指摘とそれへの答え。（数字を確かめた人と元の資料も可）
